# Angular App Harness

## Use this skill

Use the local docs in `./docs` as the source of truth for Angular work.

## Workflow

1. Read `docs/DEV-RULE.md`.
2. Read `docs/WARP.md`.
3. Read `docs/DESIGN.md`.
4. Read `docs/STANDARDS.md`.
5. Follow the repo structure and keep the diff small.

## Defaults

- Standalone Angular patterns
- SSR/BFF-safe changes
- Existing aliases and conventions first
- Minimal, boring solution over new structure
